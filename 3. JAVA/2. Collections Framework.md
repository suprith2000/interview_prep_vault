### 1. **What are the main interfaces in the Java Collections Framework?**

- **Answer**: The main interfaces in the Java Collections Framework are:
    - **Collection**: The root interface with subtypes such as List, Set, and Queue.
    - **List**: An ordered collection, allowing duplicates, with implementations like ArrayList, LinkedList, and Vector.
    - **Set**: A collection that doesn’t allow duplicates, with implementations like HashSet, LinkedHashSet, and TreeSet.
    - **Queue**: Used for holding elements before processing, with implementations like LinkedList and PriorityQueue.
    - **Map**: An interface that maps unique keys to values, with implementations such as HashMap, LinkedHashMap, and TreeMap.

### 2. **What is the difference between `ArrayList` and `LinkedList`?**

- **Answer**: `ArrayList` and `LinkedList` have different internal structures:
    - **ArrayList**: Uses a dynamically resizable array, making it faster for indexed access. However, insertion/removal operations in the middle can be slow because elements need to be shifted.
    - **LinkedList**: Uses a doubly-linked list, which allows faster insertion and deletion anywhere in the list but has slower access time for random elements.
    - **Use**: `ArrayList` is preferred for read-intensive lists, while `LinkedList` is better suited for write-heavy lists where frequent insertions and deletions occur.

### 3. **What is the difference between `HashSet` and `TreeSet`?**

- **Answer**:
    - **HashSet**: Uses a hash table for storage, making it faster (average O(1) time complexity) but doesn’t maintain any order of elements.
    - **TreeSet**: Implements a balanced binary search tree (Red-Black Tree), making it slower than `HashSet` (O(log n) time complexity) but maintains elements in natural order.
    - **Use**: `HashSet` is generally used when order doesn’t matter, while `TreeSet` is used when sorted elements are required.

### 4. **What is the difference between `HashMap` and `Hashtable`?**

- **Answer**:
    - **HashMap**: It is not synchronized, so it is not thread-safe by default. Allows one `null` key and multiple `null` values.
    - **Hashtable**: It is synchronized, meaning it’s thread-safe. Doesn’t allow any `null` key or values.
    - **Performance**: `HashMap` is generally faster than `Hashtable` because it doesn’t have the overhead of synchronization.

### 5. **Explain the difference between `ArrayList` and `Vector`.**

- **Answer**:
    - **ArrayList**: Not synchronized by default, so it’s better suited for single-threaded environments. Increases its size by 50% of its current capacity when it needs to grow.
    - **Vector**: Synchronized, which makes it thread-safe but slower in single-threaded scenarios. Increases its capacity by 100% (doubles) when it needs to grow.
    - **Use**: `ArrayList` is typically preferred due to better performance in most cases unless thread-safety is required.

### 6. **How does `HashMap` work in Java?**

- **Answer**: `HashMap` in Java uses a combination of array and linked lists (or trees in cases of hash collisions) to store key-value pairs. When a key-value pair is added, the key’s `hashCode()` method is used to determine its bucket location. If two keys produce the same hash code (collision), they are stored in the same bucket using a linked list (or a balanced tree if collisions are high). The `equals()` method is used to ensure unique keys.

### 7. **Why is `HashMap` not synchronized? How can it be synchronized?**

- **Answer**: `HashMap` is not synchronized because it’s intended for single-threaded use, and synchronization adds overhead. To synchronize a `HashMap`, it can be wrapped using `Collections.synchronizedMap()`:

### 8. **What is the difference between `fail-fast` and `fail-safe` iterators?**

- **Answer**:
    - **Fail-fast** iterators (e.g., in `ArrayList`, `HashMap`) throw a `ConcurrentModificationException` if the collection is modified while iterating, except through the iterator’s own methods.
    - **Fail-safe** iterators (e.g., in `ConcurrentHashMap`) don’t throw `ConcurrentModificationException` as they work on a clone of the collection. These iterators allow safe iteration even if the collection is modified by other threads.

### 9. **Explain how `ConcurrentHashMap` works.**

- **Answer**: `ConcurrentHashMap` is a thread-safe collection that uses a segmented locking mechanism to allow concurrent read and write operations. In Java 8 and later, it uses a combination of `CAS` operations and finer-grained locks on each bucket, allowing multiple threads to read and write simultaneously without blocking each other. It is generally preferred for concurrent access as it provides better performance than synchronizing a `HashMap`.

### 10. **What is the purpose of `Comparable` and `Comparator` interfaces?**

- **Answer**:
    - **Comparable**: Provides a natural ordering by implementing `compareTo()` directly within the class. It allows only one sort sequence.
    - **Comparator**: A separate interface, allowing custom sorting logic by implementing `compare()`. It’s useful for sorting in multiple ways.
    - **Usage**: `Comparable` is ideal for natural ordering, while `Comparator` is useful for custom orderings, such as sorting a list of people by name or age.

### 11. **Explain the `Collections` utility class.**

- **Answer**: `Collections` is a utility class in Java providing static methods for various collection operations like sorting, searching, reversing, synchronizing, and finding max/min values. Examples include `Collections.sort()`, `Collections.reverse()`, and `Collections.synchronizedList()`.
