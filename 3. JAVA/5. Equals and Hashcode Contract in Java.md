In Java, the **`equals()`** and **`hashCode()`** methods are critical when it comes to comparing objects and using objects in collections like `HashMap`, `HashSet`, or `Hashtable`. These two methods work together to determine object equality and are governed by a specific **contract**.

### **The Equals and HashCode Contract**

The contract between `equals()` and `hashCode()` defines how objects should be compared and how they should behave when stored in hash-based collections. It ensures that the objects behave consistently and predictably in collections such as `HashSet`, `HashMap`, and others.

### 1. **The `equals()` Contract**

The `equals()` method checks if two objects are "equal" according to some logic. By default, the `equals()` method in `Object` class compares object references (i.e., whether two references point to the same object in memory).

#### **Rules of the `equals()` Contract:**

- **Reflexive**: For any non-null reference `x`, `x.equals(x)` should return `true`.
- **Symmetric**: For any non-null references `x` and `y`, if `x.equals(y)` returns `true`, then `y.equals(x)` should also return `true`.
- **Transitive**: For any non-null references `x`, `y`, and `z`, if `x.equals(y)` and `y.equals(z)` are both `true`, then `x.equals(z)` should also return `true`.
- **Consistent**: Multiple calls to `x.equals(y)` should consistently return `true` or `false` as long as the objects remain unchanged.
- **Non-null**: For any non-null reference `x`, `x.equals(null)` should return `false`.

#### Example of overriding `equals()`:
```
public class Person {
    private String name;
    private int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (obj == null || getClass() != obj.getClass()) return false;
        Person person = (Person) obj;
        return age == person.age && name.equals(person.name);
    }
}

```

### 2. **The `hashCode()` Contract**

The `hashCode()` method returns an integer representation of the object. It is primarily used in hash-based collections like `HashMap`, `HashSet`, etc., to efficiently store and retrieve objects. The hash code of an object is used to quickly narrow down where the object might be located in the collection.

#### **Rules of the `hashCode()` Contract:**

- **Consistent with `equals()`**: If two objects are equal according to `equals()`, they **must** have the same `hashCode()`.
- **Consistent**: If the object’s state does not change, then calling `hashCode()` multiple times should consistently return the same value.
- **Not necessarily unique**: If two objects are unequal (according to `equals()`), they can have the same `hashCode()`, but it's best to minimize collisions (i.e., different objects having the same hash code).

#### Example of overriding `hashCode()`:
```
@Override
public int hashCode() {
    return Objects.hash(name, age);  // Automatically generates hash based on the fields
}

```

### **The Relationship Between `equals()` and `hashCode()`**

- If two objects are considered equal by the `equals()` method, they **must** have the same `hashCode()`.
- If two objects have the same `hashCode()`, they are **not necessarily equal**. This is because `hashCode()` might have collisions, meaning two unequal objects could produce the same hash code.

This relationship ensures that when objects are used in hash-based collections (like `HashSet` or `HashMap`), they are properly stored and retrieved.

### **Why Is the Contract Important?**

1. **Hash-based collections**: In collections like `HashMap` or `HashSet`, Java uses the `hashCode()` to find the bucket where an object might be located, and then it uses `equals()` to compare objects within that bucket to confirm a match.
    
    - If the `hashCode()` and `equals()` methods are not properly overridden, two equal objects might not be placed in the same bucket, leading to incorrect behavior when adding, retrieving, or checking the existence of objects in the collection.
2. **Consistency**: If the contract is violated, the behavior of hash-based collections becomes unpredictable. For example, an object that is added to a `HashSet` may not be found later, or an object used as a key in a `HashMap` may not return the expected value.
    

### **Example of `equals()` and `hashCode()` Together**
```
public class Person {
    private String name;
    private int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // Override equals method
    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (obj == null || getClass() != obj.getClass()) return false;
        Person person = (Person) obj;
        return age == person.age && name.equals(person.name);
    }

    // Override hashCode method
    @Override
    public int hashCode() {
        return Objects.hash(name, age);
    }
}

```

This ensures that:

- Two `Person` objects with the same `name` and `age` will be considered equal.
- They will have the same `hashCode()`, making them work correctly in hash-based collections.

### **Key Takeaways:**

- Always **override both `equals()` and `hashCode()` together** to ensure correct behavior in hash-based collections.
- Objects that are **equal must have the same `hashCode()`**, but objects with the same `hashCode()` don't have to be equal.
- Violating this contract can result in bugs and unexpected behavior, especially when dealing with collections like `HashSet`, `HashMap`, or `Hashtable`.
