
Aggregations in Elasticsearch allow you to analyze and summarize your data by performing operations like counting, summing, averaging, or even creating histograms and term buckets. They provide a powerful way to derive insights from your data, making Elasticsearch both a search and an analytics engine.

Here's a comprehensive guide on how to use aggregations in Elasticsearch.

### 1. **Basic Structure of an Aggregation Query**

An Elasticsearch query with aggregations consists of a `query` part (optional, for filtering/searching) and an `aggs` part that defines your aggregation logic.
```{
  "query": {
    "match": {
      "field": "value"
    }
  },
  "aggs": {
    "aggregation_name": {
      "aggregation_type": {
        "field": "field_name"
      }
    }
  }
}

```

- **query**: Optional search query to filter the documents before aggregating.
- **aggs**: Contains the aggregation(s) to perform.

### 2. **Types of Aggregations**

Elasticsearch supports various types of aggregations, which fall into four broad categories:

#### a. **Metric Aggregations**

These aggregations calculate metrics like sum, count, average, etc., over the documents.

- **Sum Aggregation**: Adds up values of a specified numeric field.
 ```
{
  "aggs": {
    "total_sales": {
      "sum": { "field": "price" }
    }
  }
}

```
    
- **Average Aggregation**: Calculates the average of a numeric field.
```
{
  "aggs": {
    "avg_price": {
      "avg": { "field": "price" }
    }
  }
}

```
    
- **Max/Min Aggregation**: Gets the maximum or minimum value of a field.
```
{
  "aggs": {
    "max_price": {
      "max": { "field": "price" }
    }
  }
}

```
    

#### b. **Bucket Aggregations**

These aggregations group documents into buckets based on certain criteria.

- **Terms Aggregation**: Groups documents by unique values in a field (like SQL's `GROUP BY`).
```
{
  "aggs": {
    "products_by_category": {
      "terms": { "field": "category.keyword" }
    }
  }
}

```
    
- **Range Aggregation**: Groups documents based on ranges of values.
```
{
  "aggs": {
    "price_ranges": {
      "range": {
        "field": "price",
        "ranges": [
          { "to": 50 },
          { "from": 50, "to": 100 },
          { "from": 100 }
        ]
      }
    }
  }
}

```
    
- **Date Histogram Aggregation**: Groups documents by date ranges, like daily, monthly, or yearly.
```
{
  "aggs": {
    "sales_over_time": {
      "date_histogram": {
        "field": "order_date",
        "calendar_interval": "month"
      }
    }
  }
}

```
    

#### c. **Pipeline Aggregations**

Pipeline aggregations allow you to perform aggregations on the results of other aggregations, useful for calculating derivatives, moving averages, etc.

- **Moving Average Aggregation**: Applies a moving average over a numeric field's values.
```
{
  "aggs": {
    "sales_over_time": {
      "date_histogram": {
        "field": "order_date",
        "calendar_interval": "month"
      },
      "aggs": {
        "total_sales": {
          "sum": { "field": "price" }
        },
        "sales_moving_avg": {
          "moving_avg": {
            "buckets_path": "total_sales"
          }
        }
      }
    }
  }
}

```
    

#### d. **Composite Aggregations**

Composite aggregations are used when you need to paginate over a large number of buckets, something that is difficult with regular `terms` aggregations.
```{
  "aggs": {
    "composite_agg": {
      "composite": {
        "sources": [
          { "category": { "terms": { "field": "category.keyword" } } },
          { "price_range": { "range": { "field": "price" } } }
        ]
      }
    }
  }
}

```

### 3. **Nested Aggregations**

You can nest aggregations within one another to analyze data across multiple dimensions. For example, you can get the average price per product category.
```{
  "aggs": {
    "products_by_category": {
      "terms": { "field": "category.keyword" },
      "aggs": {
        "average_price": {
          "avg": { "field": "price" }
        }
      }
    }
  }
}

```

### 4. **Aggregation with Filters**

You can combine aggregations with filters to apply conditions before the aggregation is calculated.
```{
  "aggs": {
    "filtered_products": {
      "filter": { "term": { "category.keyword": "electronics" } },
      "aggs": {
        "average_price": { "avg": { "field": "price" } }
      }
    }
  }
}

```

### 5. **Multi-Level Aggregations**

Elasticsearch allows for multi-level aggregations, where you aggregate within buckets. For example, finding the total sales for each category per month:
```{
  "aggs": {
    "products_by_category": {
      "terms": { "field": "category.keyword" },
      "aggs": {
        "sales_over_time": {
          "date_histogram": {
            "field": "order_date",
            "calendar_interval": "month"
          },
          "aggs": {
            "total_sales": { "sum": { "field": "price" } }
          }
        }
      }
    }
  }
}

```

### 6. **Using Multiple Aggregations in One Query**

You can run multiple aggregations at once by specifying multiple entries in the `aggs` object.
```{
  "aggs": {
    "max_price": {
      "max": { "field": "price" }
    },
    "avg_price": {
      "avg": { "field": "price" }
    }
  }
}

```

### 7. **Response Format**

The response to an aggregation query includes the aggregation results under the `aggregations` section.
```{
  "aggregations": {
    "products_by_category": {
      "buckets": [
        {
          "key": "electronics",
          "doc_count": 100,
          "average_price": { "value": 300.5 }
        },
        {
          "key": "furniture",
          "doc_count": 80,
          "average_price": { "value": 150.3 }
        }
      ]
    }
  }
}

```

### Conclusion

Aggregations in Elasticsearch allow for rich and flexible analysis on your data. Whether you need to calculate simple metrics, create buckets for categories, analyze time-series data, or perform complex calculations like moving averages, Elasticsearch's aggregation framework has you covered.

By combining metric, bucket, and pipeline aggregations, you can create powerful and complex analytics queries to extract meaningful insights from your Elasticsearch indices.
