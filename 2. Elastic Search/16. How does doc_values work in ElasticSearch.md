
**Doc values** in Elasticsearch are a data structure designed to improve search performance, particularly for sorting, aggregations, and scripting. They store the values of fields in a columnar format on disk rather than in the inverted index, allowing Elasticsearch to efficiently access and process non-text data.

### What Are Doc Values?

In Elasticsearch, fields can store their values in two main ways:

1. **Inverted index**: Used primarily for full-text search. It allows Elasticsearch to quickly find documents containing certain terms.
2. **Doc values**: These are **on-disk data structures** that store field values in a way optimized for sorting, aggregations, and computing statistics.

For each document, instead of keeping the field values in the traditional row-based format (which stores all field values for a document together), **doc values** store the field values in a columnar format. This format is ideal for quickly retrieving values across many documents.

### Why Are Doc Values Important?

Certain operations, such as sorting, aggregations, and scripting, require frequent access to field values. If Elasticsearch were to rely solely on the inverted index for such operations, it would be inefficient because the inverted index is optimized for searching text, not for retrieving and processing values.

**Doc values** provide the following advantages:

- **Efficient Sorting**: Sorting large datasets by a field value is faster with doc values since they allow quick lookups of field values for many documents at once.
- **Efficient Aggregations**: For numerical fields, aggregations (e.g., computing averages, sums, etc.) can be performed quickly because the values are stored in a format optimized for such operations.
- **Low Memory Usage**: Doc values are stored on disk (rather than in memory), which reduces memory consumption.

### How Doc Values Work

When a field in a document is indexed, its value is written to the **inverted index** (if it's a searchable field) and also to a **doc values structure** (if sorting or aggregation might be required).

#### Example: Columnar Storage

Let's assume we have the following documents:

- **Doc 1**: { "age": 25, "salary": 3000 }
- **Doc 2**: { "age": 30, "salary": 4000 }
- **Doc 3**: { "age": 22, "salary": 3500 }

In traditional row-based storage, these would be stored together for each document. However, with **doc values**, the data is stored in columns:

```
age:    [25, 30, 22]
salary: [3000, 4000, 3500]

```

When Elasticsearch needs to access the `age` or `salary` fields (e.g., for sorting), it can do so efficiently by reading the columnar data structure, without having to scan through the entire document.

### When are Doc Values Used?

Doc values are used by Elasticsearch for the following purposes:

1. **Sorting**: When you sort search results by a field, doc values allow Elasticsearch to quickly retrieve the field values for many documents and order them efficiently.
    
    Example:
```
{
  "sort": [
    { "age": "asc" }
  ]
}

```
    
2. **Aggregations**: For operations like calculating the average, sum, or other statistics on a field, Elasticsearch uses doc values.
    
    Example:
```
{
  "aggs": {
    "average_salary": {
      "avg": {
        "field": "salary"
      }
    }
  }
}

```
    
3. **Scripting**: In custom scripts that involve field values, doc values enable fast access to these values without needing to load the full document.
    
4. **Faceting**: Elasticsearch uses doc values to quickly calculate facets and breakdowns of search results.
    

### What Fields Use Doc Values?

By default, doc values are enabled for fields that support them, such as:

- **Numeric fields** (`integer`, `long`, `float`, `double`).
- **Date fields**.
- **Boolean fields**.
- **Keyword fields** (for exact matches, not analyzed text).

Doc values are **disabled** by default for text fields (i.e., fields meant for full-text search), since sorting or aggregating on text fields is usually not useful. For text fields, you would typically use **keyword** subfields if you need doc values for sorting or aggregation.

#### Example of Enabling Doc Values

If doc values are disabled for a field, you can enable them in the mapping:

```
PUT /my_index
{
  "mappings": {
    "properties": {
      "age": {
        "type": "integer",
        "doc_values": true
      }
    }
  }
}

```

You can also explicitly disable doc values if they are not needed (e.g., for fields that are never used for sorting or aggregations) to save disk space:

```
PUT /my_index
{
  "mappings": {
    "properties": {
      "description": {
        "type": "text",
        "doc_values": false
      }
    }
  }
}

```

### How Doc Values are Stored on Disk

Elasticsearch stores doc values on disk in a compressed format to reduce storage overhead. When an operation like sorting or aggregation is performed, Elasticsearch reads these values from disk and processes them efficiently in memory.

Since doc values are stored separately from the document source and inverted index, Elasticsearch can avoid reading the entire document source into memory, further improving performance.

### Example: Using Doc Values for Aggregations

Let’s say you want to calculate the average age of employees:

```
GET /employees/_search
{
  "size": 0,
  "aggs": {
    "average_age": {
      "avg": {
        "field": "age"
      }
    }
  }
}

```

In this case, Elasticsearch uses doc values to retrieve the `age` field for all documents and compute the average. Because `age` is stored in a columnar format via doc values, Elasticsearch can retrieve it efficiently without having to scan through entire documents.

### Doc Values and Fielddata

For **text fields**, which do not use doc values by default, Elasticsearch may use **fielddata** instead. Fielddata is loaded into memory and is expensive in terms of memory usage and processing time. This is why it's generally not recommended to perform sorting or aggregations on text fields.

However, for **keyword fields** (or when sorting and aggregating on numbers, dates, etc.), doc values are used instead of fielddata. This makes such operations efficient and scalable.

### Conclusion

**Doc values** play a crucial role in Elasticsearch by optimizing operations such as sorting, aggregations, and scripting. By storing field values in a columnar format on disk, they allow Elasticsearch to quickly retrieve and process these values without loading entire documents into memory. This design improves both performance and scalability, making Elasticsearch efficient for large-scale data retrieval tasks.

To summarize:

- Doc values are used for sorting, aggregations, and custom scripts.
- They store data in a columnar format on disk, which reduces memory usage and speeds up access.
- They are enabled by default for most numeric, date, keyword, and boolean fields but not for text fields
