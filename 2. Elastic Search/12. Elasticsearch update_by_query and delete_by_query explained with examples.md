
In Elasticsearch, the `update_by_query` and `delete_by_query` APIs are powerful tools that allow you to modify or remove multiple documents based on a query, without needing to retrieve and update/delete each document individually. These operations can save time and reduce overhead, especially when dealing with large datasets.

### 1. **`update_by_query` API**

The `update_by_query` API allows you to update multiple documents in an index or multiple indices that match a specific query. Unlike the regular `update` API, which targets a single document by ID, `update_by_query` can apply updates to all documents that match a given condition.

#### How It Works:

- You define a query to select the documents you want to update.
- You provide a script that modifies the documents, usually updating specific fields or adding new ones.
- The operation is performed in batches to optimize performance and avoid overwhelming the cluster.

#### Example 1: Incrementing a Field Value

Suppose you have an index of blog posts, and you want to increment the `views` field for all blog posts authored by `John Doe` by 10.

```
POST /blog_posts/_update_by_query
{
  "script": {
    "source": "ctx._source.views += params.increment",
    "lang": "painless",
    "params": {
      "increment": 10
    }
  },
  "query": {
    "match": {
      "author": "John Doe"
    }
  }
}

```

- **Script**: The `script` block defines the logic for the update. In this case, it adds 10 to the `views` field.
- **Query**: The `match` query selects documents where the `author` field is equal to `"John Doe"`.

#### Example 2: Updating Multiple Fields

You want to update the `status` to `"archived"` and set the `archived_date` for all blog posts published before January 1, 2023.
```
POST /blog_posts/_update_by_query
{
  "script": {
    "source": """
      ctx._source.status = 'archived';
      ctx._source.archived_date = params.archivedDate;
    """,
    "params": {
      "archivedDate": "2023-01-01"
    }
  },
  "query": {
    "range": {
      "publish_date": {
        "lt": "2023-01-01"
      }
    }
  }
}

```

- **Script**: Updates the `status` field to `"archived"` and adds a new field `archived_date` to each document.
- **Query**: Selects all documents where the `publish_date` is before January 1, 2023.

#### Things to Keep in Mind:

- **Non-blocking**: The operation is asynchronous, meaning you can execute it and check the progress later.
- **Partial Updates**: Like the regular `update` API, only the modified fields are updated, not the entire document.
- **Performance**: It's more efficient than retrieving, updating, and then reindexing each document one by one.

### 2. **`delete_by_query` API**

The `delete_by_query` API allows you to delete all documents that match a query. This is especially useful when you need to clean up large amounts of data in bulk, such as removing old or irrelevant documents.

#### How It Works:

- You define a query that selects the documents to be deleted.
- The delete operation is performed in batches to optimize performance and avoid overwhelming the cluster.

#### Example 1: Deleting Documents Older Than a Specific Date

Suppose you want to delete all blog posts published before January 1, 2022, from the `blog_posts` index.

```
POST /blog_posts/_delete_by_query
{
  "query": {
    "range": {
      "publish_date": {
        "lt": "2022-01-01"
      }
    }
  }
}

```

- **Query**: The `range` query selects all documents where the `publish_date` is earlier than January 1, 2022.
- **Result**: All matching documents are deleted from the index.

#### Example 2: Deleting Documents Matching a Specific Term

You want to delete all blog posts authored by `John Doe` from the `blog_posts` index.

```
POST /blog_posts/_delete_by_query
{
  "query": {
    "match": {
      "author": "John Doe"
    }
  }
}

```

- **Query**: The `match` query selects all documents where the `author` field equals `"John Doe"`.
- **Result**: All matching documents are deleted.

#### Things to Keep in Mind:

- **Performance**: The `delete_by_query` API is optimized to handle large datasets by processing documents in batches.
- **No Recovery of Deleted Documents**: Once documents are deleted, they cannot be recovered. Be cautious with this operation.
- **Throttling**: You can control the rate at which documents are deleted to avoid impacting cluster performance by using the `requests_per_second` parameter.

```
POST /blog_posts/_delete_by_query?requests_per_second=100
{
  "query": {
    "match": {
      "author": "John Doe"
    }
  }
}

```

- This example limits the delete operations to 100 requests per second.

### Advanced Usage: Controlling Task Execution

Both `update_by_query` and `delete_by_query` operations are executed asynchronously. You can monitor their progress or abort them if necessary.

#### Checking the Status of a Task

You can track the progress of long-running `update_by_query` or `delete_by_query` tasks by retrieving the task’s status:

1. Start an `update_by_query` or `delete_by_query` task.
2. Retrieve the task’s ID from the response.
3. Use the task ID to monitor progress.

`GET /_tasks/<task_id>`

#### Example Response:

```
{
  "completed": false,
  "task": {
    "status": {
      "updated": 1000,
      "created": 0,
      "deleted": 0,
      "batches": 10
    }
  }
}

```

---

### Summary

- **`update_by_query`** allows you to update multiple documents based on a query. It supports scripting to perform complex updates across many documents.
- **`delete_by_query`** lets you delete multiple documents that match a query, making it an efficient tool for large-scale document deletion.

These APIs are highly effective in managing bulk updates and deletions, minimizing the need to interact with individual documents while optimizing performance in distributed Elasticsearch clusters.
