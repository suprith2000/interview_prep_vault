
**Routing** in Elasticsearch is the mechanism by which Elasticsearch determines which shard should store or handle a specific document. By default, Elasticsearch uses a hashing mechanism based on the document’s ID to assign the document to a particular shard. However, Elasticsearch also allows users to customize this routing behavior, which can optimize search performance for certain use cases.

This guide will cover the basics of routing and then move on to more advanced routing techniques in Elasticsearch.

---

### 1. **Basic Concepts of Elasticsearch Routing**

#### 1.1. **Default Routing**

- **How It Works**: When you index a document in Elasticsearch, it automatically assigns the document to a specific shard within the index. By default, Elasticsearch uses the document’s ID and the total number of shards to calculate the appropriate shard.
- **Formula**:
```
shard = hash(_id) % number_of_primary_shards
```
    
- This approach ensures that documents are evenly distributed across the shards, balancing the load.

**Example**: When you index a document with ID `1` into an index with 5 primary shards, Elasticsearch will use the hash of `1` to determine which shard stores the document:

```
PUT /my_index/_doc/1
{
  "name": "John Doe"
}
```

Elasticsearch hashes the document ID and assigns it to one of the five primary shards.

---

### 2. **Custom Routing**

#### 2.1. **What is Custom Routing?**

- In many applications, you might want to group related documents together on the same shard. For example, if you're dealing with multi-tenant applications, you might want to ensure that all documents for a particular user or customer are stored on the same shard for faster access.
- **Custom routing** allows you to control how documents are assigned to shards based on a user-defined routing key rather than the document ID alone.

#### 2.2. **How Custom Routing Works**

- Instead of using the document’s ID to calculate the shard, you can provide a custom routing key when indexing and searching documents. Elasticsearch uses the hash of this routing key instead of the document ID to determine the shard.

**Example**: If you want to route all documents belonging to a customer with ID `123` to the same shard:

```
PUT /my_index/_doc/1?routing=123
{
  "name": "John Doe",
  "customer_id": "123"
}

```

In this case, Elasticsearch uses the hash of `123` to determine which shard will store the document, ensuring that all documents with `routing=123` will end up on the same shard.

#### 2.3. **Querying with Custom Routing**

- When you use custom routing, you must specify the same routing key when performing searches to ensure that Elasticsearch queries the correct shard.

**Example**: To query documents for customer `123`, you would include the routing key in the query:

```
GET /my_index/_search?routing=123
{
  "query": {
    "term": {
      "customer_id": "123"
    }
  }
}

```

- **Why This Matters**: If you don’t specify the routing key, Elasticsearch will need to search across all shards, which can reduce search performance. Specifying the routing key ensures that Elasticsearch only searches the shard where the documents for that customer are stored.

---

### 3. **Advanced Routing Techniques**

#### 3.1. **Use Cases for Custom Routing**

- **Multi-Tenant Applications**: In systems where you have multiple users or customers (tenants), you can use custom routing to ensure that all data for a specific tenant is stored together on a single shard. This reduces the number of shards Elasticsearch needs to query when retrieving data for that tenant, improving performance.
    
- **Geographical Segmentation**: In applications that store data across regions or geographical locations, you might route documents based on the region so that all documents from a particular location are stored on the same shard.
    
- **User-Specific Data**: For user-focused applications (e.g., social media, e-commerce), you can route documents by `user_id`, ensuring all of a user’s data is stored together.
    

#### 3.2. **Optimizing Read/Write Workloads with Custom Routing**

- **Write Optimization**: By routing documents for a specific user or tenant to the same shard, you minimize the number of shards that Elasticsearch needs to update, especially in systems with frequent updates to the same set of documents.
    
- **Read Optimization**: When querying for documents belonging to a specific routing key, Elasticsearch only needs to query a single shard, reducing query time and resource usage.
    

#### 3.3. **Balancing Routing Across Shards**

- One potential downside of custom routing is that it can lead to **imbalanced shards**. If some routing keys (e.g., customers) have significantly more documents than others, the shard holding that customer’s data can become overloaded. It’s important to consider how evenly your routing keys will distribute data across shards.

**Example**: If you have 10 shards and a few customers account for the majority of the data, those customers’ routing keys might lead to imbalances where some shards have much more data than others. This can impact performance and resource utilization.

#### 3.4. **Routing Hashes for Improved Distribution**

- If the routing key alone leads to imbalance, one approach is to append or prepend some form of additional data to the routing key to improve distribution. For example, adding a `user_type` or some other categorizing field to the routing key can help ensure a more even distribution of documents across shards.

**Example**: Instead of routing by `customer_id`, you could use a combination of `customer_id` and `region`:

```
PUT /my_index/_doc/1?routing=123-region1
{
  "name": "John Doe",
  "customer_id": "123",
  "region": "region1"
}

```

---

### 4. **Routing and Search Performance**

#### 4.1. **Improving Search Speed with Routing**

- When you know in advance which shard a particular set of documents resides on (thanks to routing), Elasticsearch can skip querying other shards, speeding up search requests.
    
- **Example**: If you only need documents related to a particular user, specifying the routing key means Elasticsearch will search only the shard holding that user's data rather than querying all shards.
    

#### 4.2. **Routing with Aggregations**

- **Aggregations**: If you need to run aggregations (e.g., `SUM`, `AVG`) across documents, routing can help by narrowing the number of shards involved in the aggregation, reducing computation time.
- However, keep in mind that when performing global aggregations, routing can lead to skewed results if only a subset of the data is considered.

---

### 5. **Best Practices for Custom Routing**

#### 5.1. **When to Use Custom Routing**

- Use custom routing when:
    - You need to optimize search performance for a specific subset of documents (e.g., documents belonging to a specific customer or user).
    - Your data access patterns are predictable, and you can group related documents by a routing key.
    - Your application involves heavy read/write operations for a specific key, and routing can help reduce the number of shards involved in each operation.

#### 5.2. **When NOT to Use Custom Routing**

- Avoid custom routing if:
    - Your data is highly dynamic and does not lend itself well to grouping by a routing key.
    - You are concerned about shard imbalances caused by uneven distribution of documents.

#### 5.3. **Monitoring and Adjusting for Shard Imbalance**

- Regularly monitor your shard sizes and usage to ensure that routing has not caused a significant imbalance in shard load. Use Elasticsearch monitoring tools like **Kibana** to visualize and manage shard health.

---

### 6. **Routing in Distributed Systems**

#### 6.1. **Routing in Multi-Node Clusters**

- In large, distributed Elasticsearch clusters, routing helps to optimize network traffic by reducing the number of nodes involved in a query or indexing operation. This becomes particularly useful when scaling up clusters across multiple data centers or regions.

---

### Summary

- **Default Routing**: Elasticsearch uses a hash of the document ID and the number of primary shards to determine where to store a document.
- **Custom Routing**: You can use a custom routing key to control how documents are distributed across shards, which can improve search and indexing performance for certain use cases (e.g., multi-tenant systems, user-specific data).
- **Advanced Techniques**: Custom routing is ideal for optimizing specific read and write workloads, though care must be taken to avoid unbalanced shards.
- **Search Performance**: Routing can significantly improve search speed when the query targets a known subset of documents.

Elasticsearch routing provides a powerful tool for optimizing the distribution of documents across shards and improving performance for targeted queries and updates. However, like any optimization, it requires careful planning to avoid shard imbalances and other potential drawbacks.
