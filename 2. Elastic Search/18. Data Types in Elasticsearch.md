
Elasticsearch supports a wide range of data types that help define the structure of your documents and how the data should be indexed, queried, and stored. These data types are categorized into core data types, complex data types, geo data types, and specialized data types. Understanding these types is crucial for optimizing performance and ensuring accurate search and aggregation results.

### Categories of Data Types in Elasticsearch:

1. **Core Data Types**
2. **Complex Data Types**
3. **Geo Data Types**
4. **Specialized Data Types**

Let’s explore each category in detail.

---

## 1. Core Data Types

These are basic data types used to store standard types of data like text, numbers, dates, and booleans. These types are essential for most indexing and querying operations.

### a) **String Types**

- **`text`**: Used for full-text search. The field value is analyzed (tokenized and transformed) during indexing.
    
    - **Example**:

```
{
  "title": { "type": "text" }
}

```
        
 **Use case**: Suitable for fields like product descriptions, where you need to search within the text.
- **`keyword`**: Used for exact matches, sorting, and aggregations. The value is not analyzed, so it's stored as-is.
    
    - **Example**:
```
{
  "category": { "type": "keyword" }
}

```
        
 **Use case**: Ideal for fields like product IDs or tags, where exact matching is required.

### b) **Numeric Types**

- **`long`**: Used for storing 64-bit signed integers.
    
    - **Example**: `{ "views": { "type": "long" } }`
- **`integer`**: Used for 32-bit signed integers.
    
    - **Example**: `{ "age": { "type": "integer" } }`
- **`short`**: Used for 16-bit signed integers.
    
    - **Example**: `{ "rating": { "type": "short" } }`
- **`byte`**: Used for 8-bit signed integers.
    
    - **Example**: `{ "status_code": { "type": "byte" } }`
- **`double`**: Used for 64-bit double precision floating point numbers.
    
    - **Example**: `{ "price": { "type": "double" } }`
- **`float`**: Used for 32-bit single precision floating point numbers.
    
    - **Example**: `{ "discount": { "type": "float" } }`
- **`half_float`**: Used for 16-bit half precision floating point numbers, useful for saving space.
    
    - **Example**: `{ "weight": { "type": "half_float" } }`
- **`scaled_float`**: Stores floating point numbers by scaling them as integers. Useful for storing large-scale numbers (like currency).
    
    - **Example**:
```
{
  "price": { 
    "type": "scaled_float", 
    "scaling_factor": 100 
  }
}

```
        

### c) **Boolean Type**

- **`boolean`**: Stores `true` or `false` values.
    - **Example**: `{ "is_active": { "type": "boolean" } }`

### d) **Date Type**

- **`date`**: Stores date and time values. Dates can be provided in different formats and queried using range queries.
    - **Example**:
 ```
 {
  "publish_date": { 
    "type": "date", 
    "format": "yyyy-MM-dd" 
  }
}

```
        

### e) **Binary Type**

- **`binary`**: Used to store binary data such as images or files in Base64 encoding. This type is not analyzed.
    - **Example**: `{ "image": { "type": "binary" } }`

### f) **Range Types**

Range types allow you to store a range of values within a single field.

- **`integer_range`**, **`float_range`**, **`long_range`**, **`double_range`**, **`date_range`**.
    - **Example**:
```
{
  "age_range": { "type": "integer_range" }
}

```
        

---

## 2. Complex Data Types

These types are used to store structured objects or arrays of values.

### a) **Object Type**

- **`object`**: Used to store JSON objects. The fields within the object can have their own mappings.
    - **Example**:
```
{
  "address": {
    "type": "object",
    "properties": {
      "street": { "type": "text" },
      "city": { "type": "keyword" },
      "zipcode": { "type": "integer" }
    }
  }
}

```
        

### b) **Nested Type**

- **`nested`**: Used to store arrays of objects where each object is indexed separately. It allows more accurate querying than `object` for arrays of objects.
    - **Example**:
```
{
  "comments": {
    "type": "nested",
    "properties": {
      "user": { "type": "keyword" },
      "message": { "type": "text" },
      "timestamp": { "type": "date" }
    }
  }
}

```

### c) **Array Type**

- **Array**: Elasticsearch does not have a dedicated array type. Any field can accept an array of values, provided all values are of the same data type.
    - **Example**:
        
```
{
  "tags": { "type": "keyword" }
}

```
        

---

## 3. Geo Data Types

These types are specialized for storing and querying geographical data.

### a) **Geo-Point**

- **`geo_point`**: Stores latitude and longitude values for location-based queries (e.g., distance-based searches, geo-bounding box queries).
    - **Example**:
```
{
  "location": { "type": "geo_point" }
}

```
        

### b) **Geo-Shape**

- **`geo_shape`**: Stores complex shapes like polygons, lines, and circles for more advanced geospatial operations.
    - **Example**:
        
```
{
  "area": { "type": "geo_shape" }
}

```
        

---

## 4. Specialized Data Types

These are advanced data types used for specific use cases like indexing IP addresses or sparse data.

### a) **IP Type**

- **`ip`**: Used to store IPv4 and IPv6 addresses. Supports efficient range queries for IP data.
    - **Example**:    
        `{   "ip_address": { "type": "ip" } }`
        

### b) **Completion Type**

- **`completion`**: Designed for efficient auto-complete or suggestion functionality. It provides a fast way to suggest results as users type.
    - **Example**:
```
{
  "suggestion": { "type": "completion" }
}

```
        

### c) **Token Count Type**

- **`token_count`**: Used to store the number of tokens generated by an analyzer for a particular field.
    - **Example**:
```
{
  "description_length": { 
    "type": "token_count", 
    "analyzer": "standard" 
  }
}

```
        

### d) **Dense and Sparse Vectors**

- **`dense_vector`**: Used to store vectors for machine learning models, particularly useful in similarity searches.
    
    - **Example**:
```
{
  "vector_field": { "type": "dense_vector", "dims": 128 }
}

```
        
- **`sparse_vector`**: Stores high-dimensional sparse vectors, useful for cases where most values in the vector are zero.

### Conclusion

Understanding the available data types in Elasticsearch is crucial for designing your index mappings effectively. Each type serves a specific purpose, allowing you to store data in an optimized format for search and analytics. Properly selecting and configuring these data types ensures efficient querying, better search accuracy, and overall improved performance.

When defining mappings for your index:

1. Use **`text`** for full-text search and **`keyword`** for exact matches.
2. Choose numeric types like **`integer`**, **`float`**, or **`scaled_float`** based on your precision requirements.
3. Use **geo** data types if you need geospatial querying.
4. Leverage **`object`** and **`nested`** types for structured data, and **completion** types for fast auto-suggestions.
