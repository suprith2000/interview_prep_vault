
In Elasticsearch, **CRUD operations** (Create, Read, Update, and Delete) are the basic operations used to interact with the data stored in an Elasticsearch index. These operations are performed via **REST APIs** and allow you to manage documents within the indices in the cluster.

Let’s break down each of the CRUD operations in Elasticsearch:

---

### 1. **Create (Indexing a Document)**

- **Operation**: Create a new document or index it.
- **Elasticsearch Method**: `PUT` or `POST`
- **Description**: The **create** operation allows you to add new documents to an Elasticsearch index. When you index a document, Elasticsearch stores it in the appropriate shard and makes it searchable.
- **Indexing a Document**:
    - If a document with a specific ID doesn’t exist, a new document is created.
    - If a document with the given ID already exists, it will be overwritten (unless you use a specific `create` operation).

**Example**:

```
PUT /my_index/_doc/1
{
  "name": "John Doe",
  "age": 30,
  "occupation": "Engineer"
}

```

- In this example, a document with an ID of `1` is created in the `my_index` index. If `my_index` doesn’t exist, Elasticsearch will create the index automatically.

**Auto-generated ID Example**:

```
POST /my_index/_doc/
{
  "name": "Jane Doe",
  "age": 28,
  "occupation": "Designer"
}

```

- In this case, Elasticsearch will create the document and auto-generate an ID for it.

---

### 2. **Read (Retrieving a Document)**

- **Operation**: Retrieve a single document or search for multiple documents.
- **Elasticsearch Method**: `GET`
- **Description**: The **read** operation in Elasticsearch allows you to retrieve documents from an index by either their document ID or via a search query.

**Getting a Document by ID**:

```
GET /my_index/_doc/1

```
- This fetches the document with ID `1` from the `my_index` index.

**Searching for Multiple Documents**: Elasticsearch provides powerful search capabilities using its Query DSL (Domain Specific Language). You can search for documents based on field values, text matching, or more complex conditions.

**Search Example**:
```
GET /my_index/_search
{
  "query": {
    "match": {
      "occupation": "Engineer"
    }
  }
}

```

- This query searches for all documents in the `my_index` index where the `occupation` field contains the word “Engineer”.

**Other Retrieval Options**:

- **Filter Context**: For filtering precise conditions (like age > 25).
- **Aggregation Queries**: To perform calculations like averages, sums, etc., on numerical fields.

---

### 3. **Update (Modifying a Document)**

- **Operation**: Update the content of an existing document.
- **Elasticsearch Method**: `POST`, `PUT`
- **Description**: The **update** operation modifies an existing document in the index without overwriting the entire document (unless explicitly specified). It allows partial updates, meaning you can update just a specific field or add a new field to a document.

**Example**:

```
POST /my_index/_update/1
{
  "doc": {
    "age": 31
  }
}
```

- This updates the `age` field of the document with ID `1` to `31`.

**Upsert Operation**:

- If a document doesn’t exist, you can use the `upsert` option to create a new document with default values if it’s not found.

**Upsert Example**:

```
POST /my_index/_update/1
{
  "doc": {
    "occupation": "Senior Engineer"
  },
  "upsert": {
    "name": "John Doe",
    "age": 30,
    "occupation": "Engineer"
  }
}

```

- If the document with ID `1` exists, it will update the `occupation` field. If it doesn’t exist, a new document is created with the values in the `upsert` section.

---

### 4. **Delete (Removing a Document)**

- **Operation**: Delete a document from an index.
- **Elasticsearch Method**: `DELETE`
- **Description**: The **delete** operation removes a document from an index. Once a document is deleted, it is no longer searchable.

**Delete by Document ID**:

`DELETE /my_index/_doc/1`

- This removes the document with ID `1` from the `my_index` index.

**Delete by Query**:

- You can also delete multiple documents based on a query. For instance, you might want to delete all documents where the `age` is greater than 60.

**Delete by Query Example**:

```
POST /my_index/_delete_by_query
{
  "query": {
    "range": {
      "age": {
        "gte": 60
      }
    }
  }
}
```

- This deletes all documents in `my_index` where the `age` field is greater than or equal to 60.

---

### Additional Notes on CRUD Operations in Elasticsearch

1. **Document Structure**:
    
    - Elasticsearch stores data in **JSON format**, making it easy to represent hierarchical and structured data.
    - Each document is stored as a **key-value pair** (e.g., `"age": 30`), and Elasticsearch allows flexible schemas.
2. **Versioning**:
    
    - Elasticsearch tracks versions of documents internally to ensure consistency in distributed systems. Every time a document is updated, its version number is incremented. This allows for **optimistic concurrency control** to avoid conflicts during updates.
3. **Optimistic Concurrency Control**:
    
    - Elasticsearch provides **versioning** to handle cases where multiple processes or users try to update the same document simultaneously. It ensures that updates are applied in the correct order without losing data.
4. **Indexing Latency**:
    
    - When you index a document, Elasticsearch doesn’t immediately make it searchable. Instead, it waits until the data has been **refreshed** (which occurs every second by default). You can trigger an immediate refresh, but doing so frequently can impact performance.
5. **Bulk Operations**:
    
    - Elasticsearch provides a **bulk API** that allows you to perform multiple CRUD operations in a single request. This is useful for batch operations to improve performance and reduce overhead.
    
    **Bulk Example**:
```
POST /_bulk
{ "index": { "_index": "my_index", "_id": "1" } }
{ "name": "John Doe", "age": 30 }
{ "delete": { "_index": "my_index", "_id": "2" } }
{ "update": { "_index": "my_index", "_id": "3" } }
{ "doc": { "age": 35 } }

```
    

---

### Summary:

- **Create**: Index a new document with `PUT` or `POST`. If the document already exists, it will be updated unless `create` is explicitly used.
- **Read**: Retrieve a document by ID or search for multiple documents using Elasticsearch's powerful search features.
- **Update**: Partially update an existing document using the `doc` option. Use the `upsert` option to create a document if it doesn’t already exist.
- **Delete**: Remove a document by ID or delete multiple documents matching a query.

These basic CRUD operations form the foundation for interacting with and managing data in Elasticsearch. They are simple to use and very powerful, especially when combined with Elasticsearch’s search and aggregation capabilities.
