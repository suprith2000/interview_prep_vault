### 1. **What is AWS Lambda?**

- **Answer**: AWS Lambda is a **serverless compute service** that lets you run code without provisioning or managing servers. You can execute your code in response to various events, such as changes in data in an S3 bucket, updates to a DynamoDB table, or incoming HTTP requests via API Gateway. Lambda automatically scales your application by running code in response to each event, and you are only billed for the compute time used (billed in milliseconds).

### 2. **How does AWS Lambda pricing work?**

- **Answer**: AWS Lambda pricing is based on:
    - **Number of requests**: The first 1 million requests per month are free. After that, you pay per million requests.
    - **Compute time**: Measured in GB-seconds. You are charged based on the amount of memory allocated to your function and the time it takes to execute, rounded to the nearest millisecond. The first 400,000 GB-seconds per month are free.

### 3. **What are the event sources for AWS Lambda?**

- **Answer**: AWS Lambda can be triggered by various event sources, including:
    - **Amazon S3** (e.g., file uploads or deletions)
    - **Amazon DynamoDB Streams**
    - **Amazon Kinesis Streams**
    - **Amazon SNS** and **SQS** (Simple Notification and Queue Services)
    - **Amazon CloudWatch** (Alarms and Logs)
    - **AWS API Gateway** (HTTP/HTTPS requests)
    - **AWS IoT**
    - **Amazon EventBridge** (formerly CloudWatch Events)
    - **Alexa Skills Kit**
    - **Custom event sources using custom integration**

### 4. **How is AWS Lambda different from EC2?**

- **Answer**: Lambda is **serverless**, meaning AWS fully manages the infrastructure, scaling, and server maintenance. You only need to provide the code. Lambda scales automatically in response to incoming events. In contrast, **EC2** provides virtual servers where you manage the infrastructure, including instance types, scaling, patching, and availability. EC2 also offers more control and flexibility but requires more manual intervention.

### 5. **What is the maximum memory and execution time allowed for a Lambda function?**

- **Answer**:
    - **Memory**: You can allocate between 128 MB and 10,240 MB (10 GB) of memory for a Lambda function.
    - **Timeout**: The maximum execution timeout for a Lambda function is **15 minutes** (900 seconds). The default timeout is 3 seconds, and you can configure this in the function settings.

### 6. **How does AWS Lambda scale?**

- **Answer**: Lambda automatically scales by creating **multiple instances** of your function to handle incoming events. Each invocation of the function runs in a separate, isolated execution environment. Lambda can handle a large number of requests simultaneously by invoking as many instances as needed. There are initial soft limits, such as **1000 concurrent executions** per account (which can be increased via a request to AWS).

### 7. **What is the cold start issue in Lambda?**

- **Answer**: A **cold start** occurs when a new instance of a Lambda function is invoked for the first time or after a period of inactivity. During a cold start, AWS needs to allocate a container, initialize the execution environment, and load your code, which causes latency (often a few hundred milliseconds or more). Once the environment is "warm," subsequent invocations of the function are faster.

### 8. **How do you minimize cold start times in AWS Lambda?**

- **Answer**:
    - **Reduce function size**: Keep your deployment package small to minimize the time it takes to load your function.
    - **Provisioned Concurrency**: Lambda’s **Provisioned Concurrency** allows you to pre-warm instances of your Lambda function to ensure they are ready to handle requests with minimal latency.
    - **Optimize initialization code**: Move heavy initialization outside the function handler so it doesn’t need to run for every request.
    - **Use lighter runtimes**: Runtimes like **Node.js** and **Python** generally have shorter cold start times compared to languages like **Java** or **.NET**, which have longer initialization phases.

### 9. **What is AWS Lambda@Edge?**

- **Answer**: Lambda@Edge allows you to run AWS Lambda functions at AWS **Edge locations** (closer to end-users) in response to Amazon CloudFront events. This enables you to execute your code closer to your users, reducing latency. Lambda@Edge is useful for tasks like **modifying requests/responses**, **custom authentication**, and **A/B testing** in CDN environments.

### 10. **How do you version AWS Lambda functions?**

- **Answer**: AWS Lambda allows you to create **versions** of your Lambda function. Every time you publish a new version, Lambda snapshots your function’s code and configuration (including environment variables and memory settings). Each version is immutable, and you can invoke specific versions of the function by using their **version number**. AWS also offers an alias system where you can point an alias (e.g., “dev”, “test”, or “prod”) to specific function versions.

### 11. **How do you handle errors in Lambda functions?**

- **Answer**: Error handling in Lambda can be done in several ways:
    - **Retry Logic**: Some event sources like **S3**, **Kinesis**, and **DynamoDB Streams** will automatically retry failed invocations. You can define retry policies for event sources like SQS.
    - **Dead Letter Queues (DLQ)**: You can configure Lambda to send failed events to **SQS** or **SNS** for later processing.
    - **CloudWatch Logs**: Lambda functions automatically log errors and execution information to **CloudWatch Logs** for further debugging.
    - **Error handling in code**: Use try/catch blocks in your code to handle exceptions and return meaningful error messages.

### 12. **What are the limitations of AWS Lambda?**

- **Answer**: Key limitations of AWS Lambda include:
    - **Execution Timeout**: 15 minutes maximum.
    - **Memory**: 128 MB to 10 GB.
    - **Package Size**: Deployment package size can be up to 50 MB (zipped) and 250 MB (unzipped).
    - **Ephemeral storage**: Lambda provides 512 MB of temporary storage in `/tmp` directory for each invocation.
    - **Concurrency limits**: Soft limit of 1000 concurrent executions per region (can be increased upon request).

### 13. **What is Provisioned Concurrency in Lambda?**

- **Answer**: **Provisioned Concurrency** is a feature in AWS Lambda that reduces cold start latency by pre-warming a specified number of function instances. It ensures that a certain number of execution environments are always ready to handle requests, which is particularly useful for applications with predictable traffic spikes or latency-sensitive applications.

- **Answer**: Yes, you can manually invoke a Lambda function using:

    - AWS SDKs programmatically by invoking the Lambda function.

### 15. **How do you pass data to a Lambda function?**

- **Answer**: Data can be passed to a Lambda function in the form of an **event** object. For example:
    - If Lambda is triggered by **S3**, the event contains details about the S3 object, such as the bucket name and file key.
    - If invoked manually or via API Gateway, you can send a JSON payload that the Lambda function processes.

### 16. **What are Lambda Layers?**

- **Answer**: **Lambda Layers** allow you to package external libraries, dependencies, or configuration files and share them across multiple Lambda functions. This helps reduce the size of the deployment package by keeping reusable code (such as libraries or SDKs) in a separate layer. A Lambda function can use up to 5 layers per invocation.

### 17. **What is a Lambda Execution Role?**

- **Answer**: A **Lambda execution role** is an IAM role that grants your Lambda function permission to access AWS resources (e.g., S3, DynamoDB) during execution. The role is attached to the Lambda function, and it uses the **IAM policy** attached to the role to determine which resources the function can interact with.

### 18. **How do you monitor AWS Lambda?**

- **Answer**: AWS Lambda integrates with **Amazon CloudWatch** to monitor performance and log output. It provides:
    - **CloudWatch Metrics**: Metrics like invocation count, error count, duration, and concurrent executions.
    - **CloudWatch Logs**: Logs generated by the Lambda function, including output from `console.log` or errors.
    - **X-Ray**: For distributed tracing to analyze and debug the performance of Lambda functions.

### 19. **What is the role of AWS X-Ray in Lambda?**

- **Answer**: **AWS X-Ray** helps in tracing requests that travel through your AWS Lambda functions, allowing you to visualize the service map, debug performance bottlenecks, and diagnose errors. You can enable X-Ray tracing in Lambda to capture metadata about the invocation and downstream services used by the function (e.g., DynamoDB or S3 interactions).

### 20. **What are the benefits of using AWS Lambda?**

- **Answer**:
    - **No server management**: You do not need to provision, patch, or manage servers.
    - **Scalability**: Lambda automatically scales based on incoming traffic.
    - **Cost-efficiency**: You only pay for what you use (billed per execution and duration).
    - **Event-driven**: Easily integrates with a wide range of AWS services and third-party services.
