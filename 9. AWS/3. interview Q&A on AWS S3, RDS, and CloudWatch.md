
### **Amazon S3 (Simple Storage Service)**

#### 1. **What is Amazon S3?**

- **Answer**: Amazon S3 is an object storage service that offers highly scalable, durable, and secure storage for any type of data. It allows users to store and retrieve any amount of data from anywhere on the web. S3 is commonly used for data backup, website hosting, and storing application assets.

#### 2. **What are S3 storage classes?**

- **Answer**: S3 offers different **storage classes** optimized for varying use cases:
    - **S3 Standard**: General-purpose storage for frequently accessed data.
    - **S3 Intelligent-Tiering**: Automatically moves data between two access tiers (frequent and infrequent) to optimize costs.
    - **S3 Standard-IA** (Infrequent Access): For data accessed less frequently but requires rapid access when needed.
    - **S3 One Zone-IA**: For infrequently accessed data stored in a single Availability Zone.
    - **S3 Glacier**: Low-cost storage for data archiving with longer retrieval times.
    - **S3 Glacier Deep Archive**: The lowest-cost storage for long-term data archiving with retrieval times ranging from 12 to 48 hours.

#### 3. **What is an S3 bucket?**

- **Answer**: An **S3 bucket** is a container for storing objects in Amazon S3. Each object in S3 is stored in a bucket. Buckets have globally unique names and are tied to specific AWS regions. Permissions and versioning can be managed at the bucket level.

#### 4. **How does S3 ensure data durability and availability?**

- **Answer**: Amazon S3 is designed for **99.999999999% (11 9’s) durability** by automatically storing copies of data across multiple Availability Zones (AZs) within a region. It also offers **99.99% availability** for S3 Standard and other storage classes, ensuring access to your data with minimal downtime.

#### 5. **What is S3 Versioning?**

- **Answer**: S3 **Versioning** allows you to keep multiple versions of an object in the same bucket. It helps protect against accidental deletion or overwriting by maintaining historical versions of files. When enabled, S3 stores every version of an object, allowing you to restore previous versions as needed.

#### 6. **What are S3 Access Control and Policies?**

- **Answer**: S3 offers several ways to control access:
    - **Bucket policies**: JSON-based policies applied at the bucket level to grant access to users, accounts, or services.
    - **Access Control Lists (ACLs)**: Fine-grained control over permissions at the object and bucket levels.
    - **IAM policies**: Manage permissions for users and groups in an AWS account to control access to S3 buckets and objects.
    - **S3 Access Points**: Simplify managing access to large datasets with unique permissions for different applications.

#### 7. **What is S3 Transfer Acceleration?**

- **Answer**: S3 Transfer Acceleration enables faster data transfers to S3 by routing traffic through **Amazon CloudFront's globally distributed edge locations**. It reduces latency and improves transfer speed, especially for users located far from the S3 bucket region.

### **Amazon RDS (Relational Database Service)**

#### 1. **What is Amazon RDS?**

- **Answer**: Amazon RDS is a managed relational database service that supports popular database engines like **MySQL, PostgreSQL, MariaDB, Oracle, and Microsoft SQL Server**. RDS automates database administration tasks like patching, backups, scaling, and hardware provisioning.

#### 2. **What are the key features of RDS?**

- **Answer**:
    - **Automated backups**: Automatically backs up databases and retains snapshots.
    - **Read Replicas**: Improves read performance by creating replicas of the primary database.
    - **Multi-AZ Deployments**: Provides high availability and failover by replicating data across multiple Availability Zones.
    - **Automatic scaling**: Supports vertical scaling of instance types and storage.

#### 3. **What is a Multi-AZ deployment in RDS?**

- **Answer**: In a **Multi-AZ deployment**, RDS synchronously replicates data to a standby instance in a different Availability Zone. This setup provides high availability and automatic failover in the event of instance failure, network issues, or AZ outages.

#### 4. **What are RDS Read Replicas?**

- **Answer**: **Read Replicas** allow you to create copies of your database for **read-heavy workloads**. They can be deployed in the same or different regions, offloading read operations from the primary database. Data is asynchronously replicated from the primary database to the read replicas.

#### 5. **How does RDS handle backups?**

- **Answer**: Amazon RDS provides two types of backups:
    - **Automated backups**: Enabled by default and includes daily backups of the database instance and transaction logs. Retention periods can be configured.
    - **Manual snapshots**: User-initiated backups that persist even if the database instance is deleted.

#### 6. **What is Amazon Aurora?**

- **Answer**: **Amazon Aurora** is a MySQL- and PostgreSQL-compatible managed database service. It is designed to provide performance and availability comparable to high-end commercial databases at a fraction of the cost. Aurora is optimized for high availability and scales automatically up to 128 TB per database instance.

#### 7. **How does RDS ensure security?**

- **Answer**: Security in RDS is ensured through:
    - **Encryption**: Data is encrypted at rest using **AWS KMS** (Key Management Service). Encryption in transit is supported via SSL.
    - **IAM roles**: Control who can administer and manage the RDS instance.
    - **VPC**: RDS instances can be deployed within a **Virtual Private Cloud (VPC)** for isolated network security.
    - **Database-specific authentication**: For MySQL and PostgreSQL, **IAM database authentication** can be used to manage access.

### **Amazon CloudWatch**

#### 1. **What is Amazon CloudWatch?**

- **Answer**: Amazon CloudWatch is a monitoring and observability service designed for DevOps engineers, developers, and system administrators. It provides real-time metrics, logs, and alarms for AWS resources and custom applications. CloudWatch helps monitor performance, troubleshoot issues, and optimize resource utilization.

#### 2. **What are CloudWatch Metrics?**

- **Answer**: **CloudWatch Metrics** are data points related to the performance of AWS services. Examples include CPU usage for EC2 instances, latency for API Gateway, and read/write operations for DynamoDB. You can also create custom metrics for applications and business KPIs.

#### 3. **What are CloudWatch Alarms?**

- **Answer**: **CloudWatch Alarms** are used to trigger notifications or actions when a metric crosses a specified threshold. For example, you can configure an alarm to send an SNS notification when an EC2 instance’s CPU usage exceeds 80% for a sustained period or to scale an Auto Scaling group.

#### 4. **What is CloudWatch Logs?**

- **Answer**: **CloudWatch Logs** allow you to collect, monitor, and analyze logs from AWS services like EC2, Lambda, RDS, and custom applications. You can create log filters to track specific patterns, create alarms based on log data, or set up retention policies for storing logs.

#### 5. **What is CloudWatch Events (EventBridge)?**

- **Answer**: **CloudWatch Events** (now part of **Amazon EventBridge**) allows you to respond to changes in your AWS environment in real-time. It can be used to trigger AWS Lambda functions, send SNS notifications, or initiate other workflows when an event occurs (e.g., an EC2 instance state change or an S3 file upload).

#### 6. **What is the difference between CloudWatch and CloudTrail?**

- **Answer**: **CloudWatch** is primarily used for monitoring and performance tracking of AWS resources (metrics, logs, alarms), while **CloudTrail** is a service that provides detailed logging of **API calls** and **user activity** within an AWS account. CloudTrail tracks who did what and when, helping with security and compliance auditing.

#### 7. **How does CloudWatch Logs Insights work?**

- **Answer**: **CloudWatch Logs Insights** is an advanced analytics service that allows you to search and analyze log data in CloudWatch Logs using a query language. You can create queries to extract, filter, and visualize log data for troubleshooting and operational insights.

#### 8. **What is a CloudWatch Dashboard?**

- **Answer**: A **CloudWatch Dashboard** is a customizable, visual interface where you can view and monitor multiple CloudWatch metrics in real-time. Dashboards can include graphs, statistics, and alarms to provide a holistic view of system health and performance across various AWS resources.

#### 9. **How do you set up custom metrics in CloudWatch?**

- **Answer**: You can publish **custom metrics** to CloudWatch using the **PutMetricData** API. Custom metrics allow you to track application-specific data (e.g., request latency, error rates) alongside default AWS service metrics. This can be done via the AWS SDK, CLI, or through AWS Lambda.
